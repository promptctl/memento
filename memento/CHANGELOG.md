## Unreleased

- feat(ceiling): a session moves the context ceiling for its project, not only for itself. `memento/skills/ceiling/bin/ceiling` takes `show`, `set <session|project> <off|N|+N|-N>` and `clear <session|project>`, and every one of them ends by printing the ceiling in force for this session, the ceiling a new session in this project would get, and the file behind each layer — so a write that is not in that output did not happen, and nothing else has to be read to find that out. Exit 0 means the files now say what the command printed; 1 that a config file or a resolved ceiling is unusable, named with the file and the line to go fix, with any `wrote` line already printed still standing, because the unusable layer can be one this command never touched; 2 that the invocation was wrong. A project-scoped change writes two files, because the user and project layers are frozen per session at that session's first stop into `sessions/<session-id>/shared-at-start.conf`: the project file alone moves the ceiling for every session after this one and not for the session that asked, which is the session that wanted headroom. Both files receive the same resolved absolute number rather than the same adjustment, and that is what makes them unable to drift apart — an absolute ignores the layers beneath it. Each is written beside its destination and moved into place only once both are staged, so the failures that actually happen — no permission, no space, a parent that cannot be made — land before either file is in force and the command exits having moved nothing rather than leaving the two files stating different ceilings. Each `wrote` line says what that file held before it — `wrote <path> line 1 (replacing 900000)` — because this session's layer is one of the two a project-scoped move writes, so the move can overwrite a ceiling an earlier `set session` pinned, and that parenthetical is the only record of the number that was there. Resolving the move before writing it also closes a bug the suite now pins: before any stop has happened there is no frozen record yet, so a project-scoped `+100_000` written as an adjustment to both files would be counted twice, the hook's first stop freezing the shared layers — the project file among them — and then applying the session's own layer on top of what it had just frozen, landing the session 100,000 tokens above the number the command reported. A project ceiling lands in whichever `.promptctl/memento.conf` is already in force at or above the anchor — `CLAUDE_PROJECT_DIR` where Claude Code sets it, otherwise the working directory — so no second file appears deeper in the tree where the hook's walk would reach it first and two files would claim one ceiling; where none stands, one is created at the repository root, found by asking git, from that same anchor, for the *common* dir so a session working in a worktree writes the checkout that worktree belongs to rather than a file that dies with it. That git call was the one lookup here that did not start from the anchor: it asked from whatever directory the process stood in, so with `CLAUDE_PROJECT_DIR` set and a shell that had `cd`'d elsewhere, `set project` could create the file in the wrong repository, or refuse with "not inside a git repository" while the anchored directory was a perfectly good one. Finding that root is how a *new* project config gets a place to be created, so it is `set project` alone that needs a repository: outside one it refuses, naming the anchor it asked git about, and the session scope still works. `clear project` removes the project layer and this session's, printing what each file held on the way out so a number someone meant to keep is recoverable from the output: later sessions return to the layer beneath the project, and this session returns to the ceiling it started under, because the frozen record still stands. It removes the project config already in force where one stands and nothing where none does, and so it asks git nothing; it used to borrow the write site, so outside a git repository with no project config it refused — with a message about failing to *write* a project ceiling, for an operation that wrote nothing and needed nothing written. In a project that never set a ceiling it now prints this session's layer alone, and the report's `project layer     (none)` line is what says the project layer is unset. `clear` also takes away a layer too broken to parse, printing what it could not read: the reader that resolves a ceiling answers an unparseable file by stopping the process, which is right everywhere a number is being computed and wrong in the one place about to delete the file — a malformed layer stops the Stop hook, Claude Code treats a dead Stop hook as non-blocking so the gate is simply off, and `clear`, the sanctioned way to remove that layer, used to die validating the very file it was asked to delete, leaving it removable by nothing but hand. The tolerance goes exactly that far: a malformed layer is still refused loudly anywhere a ceiling is resolved from it. The scope is a required word with no default, because the two differ in blast radius — one leaves a file in the repo that outlives the session and the other does not — and nothing in a person's phrasing reliably says which they meant. A negative adjustment is a value on every interpreter: `set session -50_000` is documented and accepted, but argparse decides whether a `-`-leading token is a value or an unrecognised option with a regex that matched plain digits only until 3.13 widened it, so on every Python before that — and this plugin declares no minimum — the underscored form was taken for an option, never reached the grammar, and exited 2 on a usage error instead of lowering the ceiling. That slot is marked as a value before argparse reads the line, and the suite pins it by running the command against a deliberately aged argparse, because the interpreter the suite normally runs on hides the bug. What this replaces is a dance: the skill used to have the agent hand-write the session file itself and then grep the hook's log on a later turn to learn whether the write had taken, because a config key the hook rejects does not leave the old ceiling standing — it stops the hook, which Claude Code treats as non-blocking, so the gate silently stops running for the session whose file holds it (`promptctl-context-ceiling-ab9.7ig`). Everything this command writes now goes out through one function that renders only what the hook's own parser accepts and then reads the file back, so the command's own output is the confirmation, available immediately. Hand-editing the config files is untouched and still the way a person at a terminal sets a ceiling.
- refactor(ceiling): the grammar of a written ceiling and the order the layers fold in live in `memento/lib/ceiling_config.py`, which the Stop hook and the `ceiling` command both read the layers through — one parser for the layer format, one place the layer order is decided. The hook is 244 lines, down from 394, and decides what it decided before, down to the file and line its errors name. Its suite passes unchanged but for one fixture, which now copies `lib/` alongside the hook it copies into a scratch root, because a plugin root is the whole directory rather than one script. One message changed wording: a ceiling resolving below zero reads `a ceiling of -50,000 tokens is set by <layers>, and a count of tokens is never negative`, where it used to read `<layers> resolve to a ceiling of …` and disagreed with itself whenever a single layer produced it.
- fix(ceiling): the user and project files are read once per session, at its first stop, and what they resolve to together is recorded as `sessions/<session-id>/shared-at-start.conf` — a plain config file holding an absolute number or `off`. Editing a shared file under a running session no longer moves that session's ceiling. Before this, a shared file that had held `350000` since 05:18 on 2026-09-06 lost the line at 14:55 to an agent working in an unrelated project, and every running session read the default 250,000 from its next tool call onward: one of them, at 250,196 tokens, mid-epic, in a different directory, went from unrestricted to fully gated between two consecutive tool calls, could not reach the remedy from inside the gate, and never wrote a handoff. A shared file broken into a syntax error was worse — it stopped the hook, which Claude Code treats as non-blocking, so one bad edit switched the gate off for every running session at once. A session that starts afterwards reads the shared files as they stand: an edit or a deletion gives it the new number, and a syntax error stops the hook for that session with an error, the same loud failure a malformed config has always produced. The session's own layer is unchanged: read live at every stop, applied immediately whether it raises or lowers, and deleting it returns the session to the ceiling it started under rather than to whatever the shared files say now.
- fix(message-in-a-bottle): `finalize-session` refuses a flag it does not recognise. `--help` prints the usage block on stdout and exits 0 without recording anything; any other two-dash word is named on stderr and exits 2 with nothing written; `--` ends flag parsing, so `finalize-session -- --help` still records `--help` as the message, on purpose. Every flag the launcher takes has two dashes, so a single-dash token is a near-miss of nothing — there is no short flag it could be a typo of — and `-h` or a recap line opening `- shipped the parser` records as the message it is, rather than being refused for its first character. A token carrying a newline is message text too, two dashes or not: no flag spans a line, and the close-out's handoff is routinely a multi-line recap, written at the moment a session has the least context left to spend working out why its argv came back rejected. The launcher used to recognise exactly `--goal` and `--reset`, and every other token ended the argument loop and became the handoff text, so there was no flag it could reject. Someone ran `finalize-session --help` at 2026-09-11T00:30:46Z: there is no `--help`, so the launcher recorded a handoff whose entire body was the string `--help`, exited 0, and — `--reset` having been passed in the same run — reset the session and delivered that string to the next agent as its opening prompt. That agent woke holding the word `--help` and nothing else. A typo was the same failure with nothing to notice: `--rest compact` shipped the literal text "--rest compact" as the handoff and exited 0. `--goal`, `--reset`, the default `/next` message and the transports are untouched.
- fix(message-in-a-bottle): every way `finalize-session` can give up is the launcher's own failure to report. One function prints the tool and the reason (`finalize-session: cannot create the log tempfile.`), adds a second line saying the handoff was not delivered and where it is preserved whenever the handoff has already been written, and exits 2 — the one code the usage block states for "it could not", argv, setup and transport alike. All four `mktemp` calls — one for a carried goal, three for worker logs, one per transport — used to be unguarded, so under `set -e` the launcher ended on `mktemp`'s own exit status: a code the usage block does not mention, under a message that named neither this tool nor what it was trying to write, on the one failure — a full or unwritable temp dir — where the operator most needs both. Two writes were worse still: the handoff itself and the carried goal went out as bare redirections, and a failed redirection ends the script on the redirection's own status, 1 rather than 2, under the shell's own message, which names the shell and the path but not this tool. Both are guarded now, and the handoff write names the destination it could not reach rather than offering a half-written file as preserved work. The half that matters is what happens once the handoff is on disk. The handoff is written to its durable file before any transport is chosen; the goal tempfile is created before that write, and all three log tempfiles after it. So a `mktemp` failure at a log tempfile exited 2 with the handoff already recorded and said nothing about it, leaving the operator a complete handoff sitting in a file with nothing anywhere pointing at it — and so did five further failures past that write: resolving the launcher's own path, locating the `claude` process to relaunch under the iTerm2 transport and again under the detached one, reading that process's identity, and resolving `claude` on `PATH`. All of them now say the handoff was not delivered and give its path, and the own-path failure, which named no tool at all, names this one. That notice has exactly one source: the no-transport branch — no owned pane, no reachable iTerm2 session, no `tmux` binary to spawn a window with — used to spell it out itself and now inherits it like every other refusal. The message stops at the tool and the purpose and deliberately names no directory: `mktemp -t` reads the Darwin per-user temp directory and ignores `$TMPDIR` outright, so a directory in that line would have misdirected an operator on macOS, which is the platform these transports most often run on. A failure before the write is unchanged and still reports nothing recorded, because nothing was. What changes overall is the reach of one line of the usage block: `2 it could not — argv, setup, or transport` now holds on every path out of the launcher rather than most of them.

## v0.7.0 - 2026-09-10

- feat!: the ceiling hook runs on `Stop` alone and denies nothing. On `PreToolUse` it read the count from the newest assistant record — true at a stop, stale on the first call after a tmux `/clear`, which resets a session in place, transcript and all. A session that closed out at 479,224 tokens read 479,224 again, had its first `Skill` call denied, and died having done no work. Gone with the gate: default-deny classification, shell-grammar parser, permitted-git allowlist, the allowance that let `ExitWorktree` through the refusal, misquoted-close-out rewrite message. The worktree advice stays, moved into the `Stop` instruction — the refusal a worktree session runs into is the platform's, not this hook's, so it is still told to run `ExitWorktree` with action "keep" and close out from where that leaves it. The cost is real: `Stop` only bites in a session that stops, so a long tool loop is no longer cut off mid-loop.
- feat!: `finalize-session` measures nothing. It always records the handoff, and resets the session only when passed `--reset clear|compact`. It used to reset every time it ran — the flag chose between `clear` and `compact`, never whether to reset at all — so there was no way to leave a handoff behind and keep working: writing the message cost the session its context. The stop instruction now names the flag it wants: `finalize-session --reset compact '<handoff message>'`. The flag resets on every transport; only clear-versus-compact is tmux-only, because iTerm2 and the detached transport relaunch a fresh process either way.
- feat!: nothing in the handoff message selects the reset mode. Given no `--reset`, the launcher used to read the message itself and infer `clear` or `compact` from a mention of `/compact` in the first three sentences, screened by a list of negations. That matcher had a documented misfire: "Do NOT use /compact — a blank slate is required" compacted, because a word-boundary match cannot see a negation, so the more emphatically an author forbade compaction the surer it was to happen. The screen leaves with the thing it was compensating for.
- fix(ceiling): a session already past the ceiling can raise its own ceiling, because the command that writes the session layer is no longer one the hook denies. The skill used to tell the agent to hand that command to the user to run in their own shell, which left the one session that needed headroom as the one that could not give itself any. A new ceiling now takes effect when the turn ends rather than on the next tool call, so the skill confirms the write on the following turn, where the hook's log line for it first appears.

## v0.6.0 - 2026-09-10

- feat(next)!: the `next` skill is gone. It was only a pointer to the `/next` skill that `lit init` writes into a repository (lit newer than 0.11.0), and that project skill is the one to invoke. A repository lit has not initialized now has no `/next` at all, so there the `/next` handoff that `finalize-session` sends when given no message names a skill that does not exist.
- feat(ceiling): a `ceiling` skill moves the context ceiling for the session running right now (off, up by a signed amount, or pinned to a number) by writing that session's config layer, then reads the hook's log to confirm the write took. The confirmation is the point: a key the hook does not accept stops the gate without a word, and the log is the only place that shows it. Run it before the session breaches the ceiling, because past it the gate denies every Skill call except the close-out.
- fix(message-in-a-bottle): the close-out has one trigger the agent judges for itself - the handed unit of work is complete. It also told the agent to fire when it "came within reach of the context ceiling", and not to "wait to be forced", which asked it to estimate a number only the hook can see: the hook resolves the ceiling from the config layers and reads the live count from the transcript, and the agent has neither. Sessions were throwing their context away mid-work at a third of the ceiling on the strength of that guess. The token trigger belongs to the hook, which states both numbers in the instruction it hands over once a session is genuinely past the line.
- feat!: the `MEMENTO_CONTEXT_CEILING` environment variable is gone. Three layers set the ceiling, and every one of them is a file: user, project, session. A ceiling in force is now always something written down at a path you can open, rather than something a process was started with and nothing on disk records. A session that wants its own number writes the session layer, which is what that layer is for.
- feat!: `off` is the one word that turns the ceiling off. `none`, `never` and `disabled` were three more spellings of it, so a reader of a config file had four things to recognise where the writer only ever needed one.
